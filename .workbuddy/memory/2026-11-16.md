## 追加：温度→搭配机制根因诊断（同日 23:55，仅诊断未改码）

Vivian 反馈 19.4℃ 仍推荐"过多"搭配（羽绒服级），怀疑温度机制有问题。实跑真实 DB（u_4d231921，19 件）+ 引擎复现，**她的判断成立**。完整机制与根因：

**温度→搭配链路**：真天气写 session.weather_temp → `RecommendContext.weather_temp` → ① `_target_warmth(temp)` 分段映射理想暖度（≤5→5.0 / ≤12→4.2 / ≤18→3.4 / ≤24→2.8 / ≤29→2.0 / >29→1.4）→ ② `_hard_filter` 的 F001/F002/F009-F016 按暖度硬过滤 → ③ `_score` 的 S008 按平均暖度偏差打分（gap≤0.5 +9 / ≤1 +5 / ≥2 -8，单品偏差 worst≥1.5 -2 / ≥2 -5，低温保暖+3、高温轻薄+3）→ ④ S009 面料季节 +0.5 → Top3。

**三层根因（按影响排序）**：
1. **暖度数据失真**：真实衣橱 19 件里几乎所有 `warmth_level` 都是默认占位 3，含羽绒服/羊毛大衣/T恤/板鞋；`seed_demo.py` 也是手写值。`garment_profile.effective_warmth()` 明明能从子品类推断（羽绒服5/T恤1），但 **engine.py 5 处全部直接 `it.get("warmth_level",3)`，从未调用 effective_warmth** → 推断模块形同虚设。
2. **平均暖度天然偏爱"多穿"**：`_score` S008 用 `avg_w = 所有单品暖度平均`，而 `_enumerate` 里外套/配饰是**可选附加项**（同一核心生成 4 种组合：核心 / 核心+外套 / 核心+配饰 / 全加）。多一件暖外套能把 avg 拉高、gap 缩到 ≤0.5 拿 +9；扣分项 worst 在 F014 单品级过滤后最多 1.5（只扣 -2），**加分永远大于扣分**，于是"加外套"稳定拿高分 = 系统性偏向穿多。
