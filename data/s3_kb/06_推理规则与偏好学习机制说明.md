# 06｜推理规则与偏好学习机制说明（知识库 → Agent 可执行层）

> 本文件是 S3 交付给 S1（推理引擎）、S2（前端）、S4（Agent 对话）的**接口规范**。
> 每一条规则都回指知识库中的知识点编号，任何改动都可溯源。
> 版本 v1.0

## 一、推理管线总览

```
用户自然语言需求
   ↓ ① 意图解析（S4 对话模块）
结构化需求 Request{天气, 场合, 角色, 临时偏好, 自然语言约束}
   ↓ ② 槽位候选枚举（领域一至四的枚举值）
候选单品集合 C = 上装 × 下装 × 外套 × 鞋 × 配饰
   ↓ ③ 第一层：硬性规则过滤（第二节）→ 合格方案集合 V
   ↓ ④ 第二层：偏好加权排序（第三节）→ Top-3
   ↓ ⑤ 理由生成（第四节模板）→ 输出 3 套方案 + 原理说明
   ↓ ⑥ 用户反馈 → 更新长期偏好权重（第五节）
```

## 三、第二层：偏好加权排序（Preference Layer）

### 3.1 权重公式

```
score(方案) = α · 临时偏好匹配度
            + β · 长期偏好匹配度
            + γ · 规则满足冗余度（通过硬性规则的项数越多，越"稳"）
            + δ · 多样性（新出现的单品比例，鼓励盘活闲置）
            − λ · 重复风险（同一套方案与用户近期已穿方案的相似度惩罚）
```

默认权重建议：`α=0.40, β=0.25, γ=0.15, δ=0.10, λ=0.10`（权重需在实现阶段通过样例调参，此处为初始建议值，非最终值）。

### 3.2 临时偏好匹配度 α

| 临时偏好选项 | 匹配度计算 |
|---|---|
| 色彩：亮色 | 方案中明度为"浅"或纯度为"高"的有彩色单品占比 → 1.0 亮色 / 0.5 中性 / 0.0 全暗色 |
| 色彩：暗色 | 明度为"深"的有彩色 + 无彩色占比越高越高 |
| 色彩：不限制 | 不计入该项差异，按其他维度决定 |
| 款式：基础款 | 设计款数量 = 0 → 1.0；=1 → 0.5；≥2 → 0.0 |
| 款式：设计款 | 设计款数量 ≥1 → 1.0（鼓励至少 1 件设计款，但受 R09 约束）|
| 跳过 | 该维度不计分 |

### 3.3 长期偏好匹配度 β
按第五节的属性权重表，对方案中每件单品的属性值求加权命中率。

## 四、可解释话术模板库（Reasoning Output）

> 原则：每套方案输出 **1 句总述 + 2~3 条分项理由**，每条理由必须能对应到一条具体规则或知识点，不允许出现无依据的形容词。

| 规则触发 | 话术模板 |
|---|---|
| R03 三色通过 | 「全身控制在 {n} 种颜色以内，符合三色原则。」 |
| R05/R06 气温 | 「今天 {temp}℃，{穿衣指数级别}，按标准建议选了{层级配置}。」 |
| R07 雨天 | 「有{降水}，外层选了{面料}，防风防水，湿了也不易透。」 |
| R08 温差 | 「今天温差 {diff}℃，用了三层洋葱式穿法，热了能脱、冷了能加。」 |
| R09/R10 场合 | 「{场合}属于{类别}场合，整体走{风格}路线，{禁忌规避描述}。」 |
| R11 体型 | 「按你的胸腰差（{diff}cm）判断属于 {体型} 型，{上装}修饰{部位}、{下装}让{部位}更平衡。」 |
| R12 廓形 | 「上装 {A} 配下装 {B}，{上宽下窄/上窄下宽}的对比，比全身同廓形更利落。」 |
| R13 腰线 | 「用{腰带/短外套}把腰线提到{位置}，视觉上腰身更明显。」 |
| 色彩理由 | 「{主色}做主色占约六成，{辅色}过渡，{点缀色}只在{部位}出现一次。」 |
| 临时偏好 | 「按你这次选的「{偏好}」，把{单品}放在了{位置}。」 |
| 长期偏好 | 「{M}，之前你更常选{属性}，这次也保留了这个倾向。」 |

## 五、长期偏好学习机制（Feedback Loop）

### 5.1 反馈数据结构
```json
{
  "user_id": "u001",
  "feedback": [
    {
      "outfit_id": "o20261015_01",
      "items": ["i12", "i37", "i05", "i41", "i09"],
      "rating": "like",            // like / normal / dislike
      "temp": 18, "occasion": "commute",
      "temp_pref": {"color": "dark", "style": "basic"},
      "timestamp": "2026-10-15T08:12:00+08:00"
    }
  ]
}
```

### 5.2 权重更新规则
- 初始所有属性权重 = 0。
- 每次反馈：对方案中每件单品的每个属性值执行 `weight[attr][value] += {like: +1, normal: 0, dislike: −1}`。
- **时间衰减**：近 10 次反馈权重合计占 0.7，更早的占 0.3（`w = 0.7 if in_recent_10 else 0.3`）。
- **归一化**：长期偏好匹配度 = 命中项权重和 / 命中项数，压缩到 [0,1]。
- **最小样本门槛**：某属性值被评价 ≥3 次才纳入 β 计算，否则视为中性（避免单次偶然反馈主导推荐）。
- 依据：K-ALG-08（基于反馈计数的可解释偏好权重更新，理由为稀疏反馈下计数法比模型更稳健且可解释）。

### 5.3 双层优先级的执行方式（对应答辩 Q2）
- **临时偏好**只作用于本次排序，**不写入** `weight` 表，不影响下次推荐。
- **长期偏好**由反馈累积，作用于所有后续推荐。
- 两者冲突时（例：长期偏好亮色，本次勾选暗色）：以本次为准，且**在输出中说明**「按你本次选择调整了，下次可以再切回来」，让用户感知到控制权在自己手里。

## 六、多轮对话的规则保持策略（对应核心功能 3）

| 用户指令类型 | 处理方式 | 依据 |
|---|---|---|
| 替换单品（"把长裤换成半身裙"） | 在槽位层面做替换，替换后**重跑全部硬性规则** | K-ALG-01 槽位模型 |
| 排除属性（"不要黑色衣物"） | 对该属性值设本次会话级硬约束，优先级高于长期偏好，低于 R01~R15 | K-PREF-01 |
| 调整风格（"再休闲一点"） | formal_level 临时下调 1 级，重跑 R09/R10 | K-ETQ-05 |
| 换场合（"其实是面试"） | formal_level 上调，重跑 R09/R10，可能触发方案重排 | K-ETQ-01/04 |
| 询问理由（"为什么这样配"） | 返回该方案触发的规则清单 + 话术模板，不重新生成 | 第四节 |
| 全部重来 | 清空会话级约束，重跑管线 | — |

> **工程约定**：多轮对话中，**硬性规则的重跑是必须的**——用户换了一条长裤，原方案的廓形比例（R12）可能已不成立。这一点在 S4 的 Prompt 设计中需要显式约束。
