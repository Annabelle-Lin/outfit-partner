## 一、推理管线总览

```
用户自然语言需求
   ↓ ① 意图解析（S4 对话模块）
结构化需求 Request{天气, 场合, 角色, 临时偏好, 自然语言约束}
   ↓ ② 槽位候选枚举（领域一至四的枚举值）
候选单品集合 C = 上装 × 下装 × 外套 × 鞋 × 配饰
   ↓ ③ 第一层：硬性规则过滤（第二节）→ 合格方案集合 V
   ↓ ④ 第二层：偏好加权排序（第三节）→ Top-3
   ↓ ⑤ 理由生成（第四节模板）→ 输出 3 套方案 + 原理说明
   ↓ ⑥ 用户反馈 → 更新长期偏好权重（第五节）
```

## 三、第二层：偏好加权排序（Preference Layer）

### 3.1 权重公式

```
score(方案) = α · 临时偏好匹配度
            + β · 长期偏好匹配度
            + γ · 规则满足冗余度（通过硬性规则的项数越多，越"稳"）
            + δ · 多样性（新出现的单品比例，鼓励盘活闲置）
            − λ · 重复风险（同一套方案与用户近期已穿方案的相似度惩罚）
```

默认权重建议：`α=0.40, β=0.25, γ=0.15, δ=0.10, λ=0.10`（权重需在实现阶段通过样例调参，此处为初始建议值，非最终值）。

> **⚠ 实现状态提示（v1.1）**：上述五权重公式是 S3 的设计建议，**当前引擎没有采用**。
> 实际公式见下方 3.4 节。对外讲解时不要把 α/β/γ/δ/λ 说成"系统正在用的权重"。

### 3.2 临时偏好匹配度 α

| 临时偏好选项 | 匹配度计算 |
|---|---|
| 色彩：亮色 | 方案中明度为"浅"或纯度为"高"的有彩色单品占比 → 1.0 亮色 / 0.5 中性 / 0.0 全暗色 |
| 色彩：暗色 | 明度为"深"的有彩色 + 无彩色占比越高越高 |
| 色彩：不限制 | 不计入该项差异，按其他维度决定 |
| 款式：基础款 | 设计款数量 = 0 → 1.0；=1 → 0.5；≥2 → 0.0 |
| 款式：设计款 | 设计款数量 ≥1 → 1.0（鼓励至少 1 件设计款，但受 R09 约束）|
| 跳过 | 该维度不计分 |

### 3.3 长期偏好匹配度 β
按第五节的属性权重表，对方案中每件单品的属性值求加权命中率。

> **实现状态（v1.3 更新）**：第五节的属性权重法**已落地**（2026-11-24）。画像存 `User.profile_prefs` = `{"color": {"蓝": {"w": 3, "last": "..."}}, ...}`，反馈按命中属性 ±1；S003 已改为真·逐值匹配（命中 w>0 加分、w<0 扣分，封顶 ±3）。时间衰减由「近 10 次 0.7/0.3」调整为**半衰期 30 天**的连续衰减 `w × 0.5^(age/30)`，读取时计算不写库；`|有效权重|<2` 视为中性（替代原「≥3 次样本门槛」）。
> 旧五维 0–10 标量分（pref_color 等）保留兼容旧接口，无画像时 S003 回落到旧口径。

### 3.4 当前实现的打分公式（v1.1 新增，对外解释以此节为准）

```
score(方案) = 60.0 基础分
            + S001  临时偏好-颜色命中        +2.0
            + S002  临时偏好-款式命中        +2.0
            + S003  长期偏好偏离中性值        ±(偏离幅度 × 0.5)
            + S004/S005/S006  色彩协调       +1.0 / +0.8 / +0.5（三选一）
            + S007  上宽下窄版型              +1.0
            + S008  26℃穿衣法保暖契合         +9 / +5 / +1 / −5；穿多再 −4
            + S009  面料季节适配（按 season） +0.5
            + S010  雨天闭合鞋                +2.0（仅雨天）
            + S011/S012  体型适配             +1.0 / −1.0
            + S013  洋葱式分层（≥2 层）       +2.0
            + S014  三明治三层齐全             +1.5（雨天内外两层 +1.0）
            + S015  风格轴一致性              −4 / +3 / +1.5
            + S016  正式度契合场合            +2 / +0.5 / −3
最终分数裁剪到 [0, 100]。
```

**与设计稿的三个关键差别**：
1. **打分制不同**：设计稿是多个 0–1 归一权重相加，实现是 60 分基础分 + 离散加减项。
2. **主导维度不同**：实现里权重最大的是 S008 温度契合（跨度 14 分），其余多为 0.5–3 分的小项。设计稿里 α 临时偏好（0.40）权重最高。
3. **五个归一化权重未使用**：γ（规则冗余度）、δ（多样性）、λ（重复风险）在实现中都没有对应项。Top-3 的多样性只靠「至少换掉一件单品」的贪心去重的实现，不是 δ/λ 计算。

## 四、可解释话术模板库（Reasoning Output）

> 原则：每套方案输出 **1 句总述 + 2~3 条分项理由**，每条理由必须能对应到一条具体规则或知识点，不允许出现无依据的形容词。

| 规则触发 | 话术模板 |
|---|---|
| R03 三色通过 | 「全身控制在 {n} 种颜色以内，符合三色原则。」 |
| R05/R06 气温 | 「今天 {temp}℃，{穿衣指数级别}，按标准建议选了{层级配置}。」 |
| R07 雨天 | 「有{降水}，外层选了{面料}，防风防水，湿了也不易透。」 |
| R08 温差 | 「今天温差 {diff}℃，用了三层洋葱式穿法，热了能脱、冷了能加。」 |
| R09/R10 场合 | 「{场合}属于{类别}场合，整体走{风格}路线，{禁忌规避描述}。」 |
| R11 体型 | 「按你的胸腰差（{diff}cm）判断属于 {体型} 型，{上装}修饰{部位}、{下装}让{部位}更平衡。」 |
| R12 廓形 | 「上装 {A} 配下装 {B}，{上宽下窄/上窄下宽}的对比，比全身同廓形更利落。」 |
| R13 腰线 | 「用{腰带/短外套}把腰线提到{位置}，视觉上腰身更明显。」 |
| 色彩理由 | 「{主色}做主色占约六成，{辅色}过渡，{点缀色}只在{部位}出现一次。」 |
| 临时偏好 | 「按你这次选的「{偏好}」，把{单品}放在了{位置}。」 |
| 长期偏好 | 「{M}，之前你更常选{属性}，这次也保留了这个倾向。」 |
| S015 风格一致（v1.1 补） | 「{单品A}与{单品B}同为{风格}路线，整体风格统一。」／「避开了{风格X}与{风格Y}的互斥组合。」 |
| S016 正式度（v1.1 补） | 「单品正式度与「{场合}」要求接近，不会过于随意或过于隆重。」 |

> 其中 R04/R07/R13/R14/R15 相关模板属于**设计稿预留**，当前代码不产出对应话术。

## 五、长期偏好学习机制（Feedback Loop）

### 5.1 反馈数据结构
```json
{
  "user_id": "u001",
  "feedback": [
    {
      "outfit_id": "o20261015_01",
      "items": ["i12", "i37", "i05", "i41", "i09"],
      "rating": "like",            // like / normal / dislike
      "temp": 18, "occasion": "commute",
      "temp_pref": {"color": "dark", "style": "basic"},
      "timestamp": "2026-10-15T08:12:00+08:00"
    }
  ]
}
```

### 5.2 权重更新规则
- 初始所有属性权重 = 0。
- 每次反馈：对方案中每件单品的每个属性值执行 `weight[attr][value] += {like: +1, normal: 0, dislike: −1}`。
- **时间衰减（2026-11-24 实现口径）**：`w_eff = w × 0.5^(age_days / 30)`，半衰期 30 天；读取时算，不写库。原设计的「近 10 次 0.7 / 更早 0.3」在反馈量小时过于跳变，改为连续衰减。
- **归一化**：S003 逐值匹配命中 w_eff 求和，封顶 ±3 分，避免画像锁死推荐。
- **最小样本门槛（实现口径）**：`|w_eff| < 2` 的属性视为中性，不参与 S003；等价于原「≥3 次样本」但更平滑（单次强反馈也可能达标）。
- 依据：K-ALG-08（基于反馈计数的可解释偏好权重更新，理由为稀疏反馈下计数法比模型更稳健且可解释）。

### 5.3 双层优先级的执行方式（对应答辩 Q2）
- **临时偏好**只作用于本次排序，**不写入** `weight` 表，不影响下次推荐。
- **长期偏好**由反馈累积，作用于所有后续推荐。
- 两者冲突时（例：长期偏好亮色，本次勾选暗色）：以本次为准，且**在输出中说明**「按你本次选择调整了，下次可以再切回来」，让用户感知到控制权在自己手里。

## 六、多轮对话的规则保持策略（对应核心功能 3）

| 用户指令类型 | 处理方式 | 依据 |
|---|---|---|
| 替换单品（"把长裤换成半身裙"） | 在槽位层面做替换，替换后**重跑全部硬性规则** | K-ALG-01 槽位模型 |
| 排除属性（"不要黑色衣物"） | 对该属性值设本次会话级硬约束，优先级高于长期偏好，低于 R01~R15 | K-PREF-01 |
| 调整风格（"再休闲一点"） | formal_level 临时下调 1 级，重跑 R09/R10 | K-ETQ-05 |
| 换场合（"其实是面试"） | formal_level 上调，重跑 R09/R10，可能触发方案重排 | K-ETQ-01/04 |
| 询问理由（"为什么这样配"） | 返回该方案触发的规则清单 + 话术模板，不重新生成 | 第四节 |
| 全部重来 | 清空会话级约束，重跑管线 | — |

> **工程约定**：多轮对话中，**硬性规则的重跑是必须的**——用户换了一条长裤，原方案的廓形比例（R12）可能已不成立。这一点在 S4 的 Prompt 设计中需要显式约束。

## 八、实现差异清单与配置说明（v1.1 新增）

### 8.1 规则 JSON 的定位（重要，调参前必读）

`rules/filter_rules.json` 与 `rules/score_rules.json` **只用于登记规则来源和展示，不驱动推荐行为**。
真正执行逻辑写死在 `app/agent/engine.py` 的 `_hard_filter()` 与 `_score()` 里。
**改 JSON 里的权重或阈值不会改变推荐结果**。要调行为，必须改代码。

已发现的具体不一致（截至 2026-11-23）：

| 项目 | JSON 登记 | 代码实际 |
|---|---|---|
| S010 | ~~「新鲜度」，7 天未穿加分~~ | 「雨天鞋履适配」，雨天穿闭合鞋 +2。**v1.1 已修正 JSON 登记**，与代码一致 |
| S003 | 「按品类/色系/风格/松量逐值匹配」 | 「画像分偏离中性值 5 的幅度 × 0.5」，不逐值匹配 |
| S009 | 「面料季节适配」 | 实际只读 `season` 字段，不读 `fiber` / `thickness`（与 03 文档 3.5 节的映射表无关） |
| F001 | 禁止项含「薄裙」 | 禁止项为「短裤、短袖、吊带、背心、凉鞋」，不含薄裙 |
