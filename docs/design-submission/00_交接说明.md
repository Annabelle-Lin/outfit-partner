### 2.2 领域 Agent（核心亮点，务必写足）

| 成果 | 位置 | 作用 |
|---|---|---|
| 推理引擎 | `app/agent/engine.py` | 规则约束 + 打分排序，生成候选搭配并给出理由点 |
| 知识库检索 | `app/agent/kb.py` | 领域知识切片索引与检索，作为 LLM 参考资料（RAG） |
| LLM 调用层 | `app/agent/llm.py` | **文本 DeepSeek（deepseek-flash）、视觉智谱 GLM-4V-Flash（glm-4v-flash）**；`classify()` 统一裁决 domain+intent、`ask()`/`ask_stream()` 生成与 SSE、`trend()` 潮流资讯、`check_domain()` 能力白名单、`weather_reply()`、`analyze_image()` 视觉识别；关闭思考模式、含超时降级 |
| 衣物画像 | `app/agent/garment_profile.py` | 单品属性归一与画像构建 |

**架构要点（写概要设计时直接引用）**：分层为「前端 → 接口层 → Agent 引擎 → 规则库/知识库 → 数据层」。Agent **不是纯 LLM**，而是「规则引擎负责可行性与打分（可解释、可复现）+ LLM 负责自然语言解释、意图裁决与追问」。意图识别采用 **LLM 主裁决 + 本地护栏**：先由 LLM 一次判定 domain 与 intent，本地规则只做后置槽位提取与窄修正，外部问题无权翻案——避免用闭集关键词词表对抗开放语言造成误判。LLM 不可用时降级为模板回复与本地兜底。这是本项目与普通 ChatGPT 套壳的关键区别，也是评分点。
