# 接口清单表

> 本表依据 **2026-11-19 当前代码实际路由**统计，共 **38 个业务端点**，分属 **7 个接口模块**（user / clothing / weather / chat / feedback / purchase / upload）。除标注「免鉴权」的接口外，其余均需在请求头携带 `Authorization: Bearer <token>`，并按 `user_id` 做数据隔离。统一响应结构为 `{code, msg, data}`，业务成功 `code=0`。
>
> 实现状态口径：**38 个端点全部已实现、可调用**。对话模块由「LLM 主裁决 + 本地护栏」驱动——文本用 DeepSeek（deepseek-flash）、视觉用智谱 GLM-4V-Flash（glm-4v-flash），SSE 流式问答已启用；上传识别在配置 `ZHIPU_API_KEY` 时走视觉模型，未配置时降级为本地启发式（返回 `source=heuristic, degraded=true`）。天气接口在外部服务失败时如实返回 `source=unavailable` + 空温度/空预报，不返回伪造数据。
>
> 字段级入参与出参明细见 `docs/项目文档/API_CONTRACT.md`（v0.4 历史快照，记录 22 个接口）与 `app/schemas.py`；**端点数量与实现状态以本表为准**。

## 九、口径说明

`API_CONTRACT.md` 冻结于 v0.4 版本（2026-10-21，记录 22 个接口），其字段级说明仍有参考价值，但**端点数量与实现状态以本表为准**。本表按 2026-11-19 代码实际路由统计，已纳入其后新增/完善的端点：会话单条删除与批量删除、未来天气预报、衣橱 Excel 导出、SSE 流式问答、反馈影响与撤销、以及潮流资讯双栏配图所依赖的返回字段。新增字段不设新 API 路径（如 `images[]` 复用 `/chat/{session_id}/message` 响应），前端动态创建节点、不新增静态 id，因此契约基线校验保持通过。
