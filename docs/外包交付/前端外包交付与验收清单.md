## 0. 先看这一条：你的前端是什么形态

这是决定"能不能丝滑更新"的根本，外包前必须先讲清楚：

| 事实 | 现状 | 对交付的影响 |
|---|---|---|
| 文件数量 | 只有 1 个 `index.html` | 没有"源码目录"，改动全部落在同一个文件里 |
| CSS | 1 个 `<style>` 块，29,338 字符 | 样式内联，不在 .css 文件里 |
| JS | 1 个内联 `<script>`，112,251 字符，141 个函数 | 业务逻辑和模板字符串混在一起 |
| 构建链 | **无**（无 package.json / vite / webpack / tailwind / tsconfig） | 交付物必须保持"双击即用"，不能引入 npm |
| 部署方式 | FastAPI `app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True))` | 后端直接把 `frontend/` 目录当静态根，**不改后端代码就不能改目录结构** |
| 外部依赖 | 仅 Google Fonts 的 3 个 `<link>`（Fraunces / Noto Serif SC / Noto Sans SC / Manrope） | 唯一的外网依赖，也是唯一可协商的替换点 |

**结论**：这是一个"无构建、单文件、纯静态"的前端。你要守住的不是"代码风格"，而是**接口约定**——保住 id、函数名、接口路径，样式随便改；一旦动了这三样，功能就会断。

## 二、要叮嘱他的 7 条红线

按"最容易出事"排序：

### 红线 1｜不许改 id
111 个 HTML id + 83 个 JS 抓取点。`getElementById('auth-submit')` 一旦变成 `id="auth-btn"`，登录按钮就死了，而且**页面看起来正常**，只是点了没反应——最难查的一类 bug。

> 允许：加 class、包一层 div、调整位置
> 禁止：改 id 名、删 id、同一 id 出现两次

### 红线 2｜不许改 onclick 函数名
37 个函数、99 处内联绑定，例如 `onclick="rateOutfit(this,'like')"`。函数名和参数顺序都不能动。**少绑一处也算违规**——校验脚本按次数比对。

### 红线 3｜不许动 16 个接口路径和字段
16 个路径、27 处调用。`_api('/api/v1/feedback', ...)` 里的路径、请求体字段名（`user_id` / `rating` / `tags` / `comment`）必须原样。字段名一改，后端 422；路径一改，直接 404。

### 红线 4｜CSS 变量只改值，不改名
28 个设计令牌（`--paper` / `--ink` / `--clay` / `--r-md` …）。想换配色就改 `--clay:#B5836E` 的值，但**变量名不能变**，因为 189 个 class 都在引用。

> 这是"换皮"最安全的方式：改值 → 全站风格统一变；改名 → 大面积样式失效。

### 红线 5｜不许引入构建链
你没有 node 环境，部署是 FastAPI 直接托管静态目录。如果对方给你一个 `dist/` 让你 `npm run build`，你就被套住了。

> 允许：原生 CSS（含嵌套）、原生 ES6、内联 SVG
> 禁止：tailwind 编译、SCSS 编译、React/Vue 重写、打包产物

### 红线 6｜不许破坏 3 个 localStorage 键
`wardrobe_token` / `wardrobe_uid` / `wardrobe_chat_sid`——登录态和会话续接全靠它们。改了就要求用户重新登录。

### 红线 7｜不许改 `frontend/` 目录结构
后端 `app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True))` 写死了这个目录。想拆成 `index.html + app.css + app.js` 可以，但**必须仍在 `frontend/` 下、仍以 `index.html` 为入口**，且要同步给你一份可回滚的单文件版。

## 四、取回交付物后的"丝滑更新"流程（5 步，约 15 分钟）

```bash

# 3. 跑契约校验（关键！先看有没有踩红线）
python scripts/check_frontend_contract.py
#    对比 index-anchors.json：id / onclick / 函数 / 接口 / 存储键 是否齐全

# 4. 跑后端回归（只确认后端没被误伤；前端改坏它查不出来）
PYTHONPATH=. C:/Python311/python.exe scripts/phase1_test.py   # 期望 PASS=19 FAIL=0
#    smoke_test.py 不存在，别写进流程

# 5. 人工补查校验脚本的 3 个盲区（见下文）

# 6. 视觉验收：8 个页面在新旧之间来回切，重点看移动端
#    通过后合并
git checkout main && git merge review/design-v1
```

> 环境提示：`python3` 在当前 shell 指向 WorkBuddy 内置 3.13（没装 fastapi），直接跑 `phase1_test.py` 会 `ModuleNotFoundError: No module named 'app'`。必须用 `C:/Python311/python.exe` 且带 `PYTHONPATH=.`。契约脚本只用标准库，任意 Python 都能跑。

**为什么第 3 步仍然最重要**：其余 6 类锚点它确实能在 2 秒内拦住，省掉你手动点 8 个页面找事故。

**但它有 3 个已实证的盲区，实测都放行，必须人工补查**：

| 改坏方式 | 脚本结果 | 人工怎么查 |
|---|---|---|
| `onclick="rateOutfit(this,'like')"` → `rateOutfit(null,'hate')` | 放行 | 全文搜 onclick，比对 99 处参数，尤其 `this` 和 `'like'/'normal'/'dislike'` |
| 新增一个重复 id（如再加个 `id="auth-submit"`） | 放行 | 控制台执行 `[...document.querySelectorAll('[id]')].map(e=>e.id).filter((v,i,a)=>a.indexOf(v)!==i)`，应返回空数组 |
| 改掉 JS 依赖的 class（`chip` → `zzz-chip`） | 放行 | 核对 10 个 class 仍在 HTML：`chip`/`msg-bubble`/`nav-item`/`opt-chip`/`outfit-note`/`rate-btn`/`rate-extra`/`rate-extra-input`/`seg-option`/`weather-stats` |
